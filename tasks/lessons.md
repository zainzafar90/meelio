# Lessons

- 2026-04-04: Do not use product or marketing labels in package, directory, file, type, or symbol names unless the user explicitly asks for that naming. Default to neutral functional names like `focus-dashboard`, `daily-focus-plan`, or `today-dashboard`.
- 2026-04-05: When the user provides visual feedback that the UI "doesn't look good", do not keep tuning contrast or effects on the same composition. Re-evaluate the spatial hierarchy first and remove heavy containers before adding more styling.
- 2026-04-05: On wallpaper-first home screens, do not stack multiple large center-aligned text blocks with inherited component margins. Home needs one dominant center line, one supporting line, and a separate lower band for quote/dock content.
- 2026-04-05: Do not remove useful shell structure like ambient top pills unless the user asked for that simplification. Reduce their prominence first. Also never repeat the same semantic content in both pills and center copy.
- 2026-04-05: Ambient pills on wallpaper-first shells should never use heavy dark outlines. Favor soft borders, subtle fills, and atmospheric contrast over explicit strokes.
- 2026-04-05: When a wallpaper-first UI starts feeling "outlined everywhere", remove stroke-based separation across the whole shell family, not just one component. Use fill, blur, and shadow as the primary separators.
- 2026-04-05: When cleaning up shell chrome, preserve intentional atmospheric blur. Remove harsh strokes first; do not flatten blur-backed focus surfaces unless the user asks for a flatter style.
- 2026-04-05: Do not keep “improving” responsiveness after the user says a recent responsive state was good. If the user liked the last responsive version, preserve that layout baseline and isolate later visual tweaks from width/height behavior.
- 2026-04-05: Fix small-screen overlap at the component-content level first. Prefer hiding/compressing pill internals on narrow widths over changing the shell flex structure if the broader layout was already working.
- 2026-04-05: For responsive pill behavior, follow the user's pattern: on very small widths keep `icon + value`, tighten the gap, and hide the label; on `sm+` restore `icon + label + value`. Do not solve pill overlap by rewriting parent flex/layout first.
- 2026-04-05: If an action changes product state in a non-obvious way, do not ship it as an unlabeled icon-only control. Use plain language like `Focus` or `Focused` so the user does not have to infer semantics from a star or pin glyph.
- 2026-04-05: Starting a primary workflow should not auto-open secondary sheets unless the user explicitly asked for that panel. Enabling soundscapes can affect playback, but it should not force the soundscape sheet open during `Start Focusing`.
- 2026-04-07: When asked to translate “new changes between branches,” do not stop at changed locale JSON files. Audit the actual branch diff for newly introduced hardcoded UI strings in changed components and helpers, especially screenshot-visible shell copy.
- 2026-04-07: When Zen Mode temporarily takes over another system like site blocking, do not treat session entry as equivalent to “active focus.” Bind that subsystem to the real focus state transitions (`focus`, `break`, `pause`, reset) so Zen can enable the capability without leaving it active out of focus.
- 2026-04-07: For wallpaper-first Zen surfaces, preserve the frosted atmospheric treatment but do not stack it everywhere and never introduce hard black outline borders around pills or controls. Calm comes from fewer framed objects, softer fills, and cleaner hierarchy, not stronger strokes.
- 2026-04-08: For blur-backed Zen controls, do not animate the opacity of the blur surface itself or pair it with dark border/shadow treatments. Keep the backdrop blur mounted continuously and animate only the white fill/text emphasis so the reveal stays smooth and never reads as outlined.
- 2026-04-08: When Zen controls and the dock share the lower shell, do not keep them on the same bottom offset. Active Zen controls need their own higher lane above the dock, and if the user asks for white action buttons, make both actions consistently white instead of mixing one white control with one muted control.
- 2026-04-08: White Zen action buttons should only hit strong white in the revealed state. In the quiet state, keep the blur mounted but dim the content emphasis substantially; otherwise focused-out still looks active.
- 2026-04-08: For active Zen controls, `windowFocused` is too broad as a reveal trigger. Use short-lived mouse activity plus direct hover/focus-within so the quiet state remains quiet until the user actually moves toward the controls.
- 2026-04-11: When extracting a large React component, do not replace inline complexity with prop-sprawl. Presentational shells should receive a small number of cohesive view-model objects, not a long flat list of labels/values/ids that recreates the original mess at the boundary.
- 2026-04-11: If a top-level React container mainly forwards view models and handlers into sibling shells, stop and remove the prop routing. Use a local feature context or colocated shell hooks so mode components can read dashboard state directly without heavy prop drilling.
- 2026-04-11: Do not centralize raw store selection, translation copy, derived labels, status-item builders, and feature flags into one mega `use*ViewModel` hook. Split it into adjacent state-selection and derived-state hooks, with shared feature types in their own file.
- 2026-04-11: On Zen CTA popovers, do not repeat generic state words like `Ready` in both the trigger and the body. The trigger should read like an action, and the body should summarize included modules and exceptions without per-item `Ready` repetition.
- 2026-04-11: When a Zen shell is described as cluttered, reduce prominence before adding new structure. Soften pill contrast/shadow, restore small semantic icons where they improve scanability, and lighten supporting text rather than introducing more containers or labels.
- 2026-04-11: On compact Zen popovers, do not let the headline exceed the scale of the actions and summary chips by too much. Keep it clearly primary, but closer to `xl/2xl` territory so the panel still feels compact.
- 2026-04-11: When the user asks for only three typography levels on a compact surface, enforce exactly that: one heading scale, one body scale, and one shared CTA/action scale across chips and buttons. Do not leave near-duplicate `xs/sm/base` variants fighting each other.
- 2026-04-11: On Zen popover exception rows like `Tab Stash Off`, typography still counts toward the three-level system. Exceptions can be dimmer than active chips, but they cannot introduce a fourth label/value scale or overly letter-spaced style.
- 2026-04-11: If Zen status items are meant to read as a pill set, active and inactive states must share the same container shape and spacing. Only tone should change; do not drop inactive items into a raw text row.
- 2026-04-11: If the user asks for check/minus status pills, stop splitting Zen modules into included vs exception groups. Render all modules through one pill component and vary only the status icon and tone.
